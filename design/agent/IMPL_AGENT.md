# Agent（Code 与 Agent 管理）· 实现规范（本地版）

给本机 Claude Code 用。仓库根目录是 Momoko（Go Kratos 后端 + `frontend/` Vue 3 前端）。
这是一个**新功能**：Momoko 作为 ACP（Agent Client Protocol）客户端，在服务器上启动并控制 Claude Code、Codex 等 Agent，用户直接在 Momoko 网页里写代码；同时管理会话、工作区、模型供应商（官方账号和第三方接口）、MCP、技能、运行时和通知。

## 0. 先读

1. 本目录的原型（清单见 `README.md`）。原型已经和用户逐条确认过，布局、信息和每个控件的行为以原型为准。
2. `../IMPL_BRIEF.md`：前端通用规范（令牌只用 `--m-*`、通用组件、三语文案写在 `frontend/src/locales/extra/<模块>.ts`、`?tab=` 页内标签、检查命令）。这里全部沿用。和它冲突的只有第 1 节的「尺寸和字」：Agent 页面的内容区比其它页面紧凑。
3. 原型的读法同 `../project/`：不要搬 HTML 或 CSS 类，用项目组件实现同样的布局和信息。原型里的数据是示例；用户能看到、有意义的信息，后端没有就补上，不写兼容分支。
4. 第 3 节的 ACP 对照表和第 9 节的实测清单。**原型里有几处依赖 ACP 里还没定稿、或者适配器未必支持的能力**，实现前先实测，Agent 不给的东西界面上就不显示，不估算、不编数字。

## 1. 用户反馈过的硬性要求（实现时逐条自查）

**外壳和观感**
- **不动 Momoko 的外壳**：侧边栏、顶部搜索栏、通知铃铛、页头和标签页都用项目现有的。Code 页用收起成图标栏的侧边栏，Agent 管理用展开的侧边栏。只改内容区。
- **内容区紧凑且圆角**，参考 Codex / Claude 桌面端的密度和层级，但用 Momoko 自己的圆角形状，不要方角：按钮高约 30（小号 26）、胶囊形；图标按钮 26–30、圆角 8–9；输入框和表单字段 32、圆角 10；开关 34×20；列表行约 50；菜单项 30、菜单圆角 12；卡片和面板圆角 14–16；弹窗宽约 560、圆角 16、标题 15 左右。
- **字要小、要轻**：内容区正文和行标题 13，说明 12，标签类 11.5；字重最多到 600，只给标题、当前项、行名称；按钮和标签 500。内容区用普通界面字体（Segoe UI / 微软雅黑 UI / 苹方），外壳保持 Outfit。
- **层级**：分组标题 → 圆角列表卡片 → 一行一项（名称加一行说明，操作在行尾）。不用大卡片、贴纸头像和成块的键值说明。
- **不放「这是怎么工作的」说明块**，页头副标题只放数量。
- **同一件事只在一个地方决定**，不重复加限制：没有「工作区范围」、没有「哪些工作区能用这个 MCP / 技能」、没有全局的「允许跳过全部确认」开关、工作区不单独选默认 Agent 和默认供应商（选了默认模型就定了）。
- **弹窗画在页面里**，每个画出来的控件都要有真实效果。
- 菜单里这个功能叫 **Code**，管理入口叫 **Agent 管理**。

**Code 页（`Main.dc.html`、`AgentNewPC.dc.html`、`AgentMobile.dc.html`）**
- 三栏：会话栏、中间（标签页 + 对话或文件）、右侧面板；左右两栏都能收起。
- 会话栏按「工作区 → 会话」分层：工作区一行，可折叠，名称后面带 Git 分支；悬停出现「⋯」（信息卡：分支、会话数、目录、编辑工作区）和「+」（在这个工作区新建会话）。会话每条一行：状态点、标题、Agent 标记；超过 4 个先显示 4 个，下面「展开显示」。不属于任何工作区的会话归在「无工作区」。
- 会话菜单：重命名、**复刻对话**、**在新工作树里复刻**、（移到外层）、导出记录、归档、删除。复刻的是对话；「在新工作树里复刻」是把复刻出来的对话放到一个新工作树里跑，工作树名字自动生成，不让用户填。复刻出来的会话缩进排在主会话下面；可以「移到外层」，之后不再缩进、删主会话时也不带上它，但会话信息里保留「复刻自」。删除主会话时询问是否连同复刻出来的会话一起删，不勾就把它们移到外层保留。**没有**「切换或新建分支」。
- 中间上方是标签：第一个是对话，后面是打开的文件和子 Agent 的会话。标签多的时候不挤压别的组件，用右侧的「全部标签」菜单切换。
- 对话里：思考过程可展开收起；工具调用一行一个；改动有内联 diff；需要批准时出批准卡片；一轮结束有一行摘要，带可展开的 token 用量。
- 输入框：进行中且输入为空时，发送按钮变成停止，有输入才变回发送；附件、`@` 引用文件、`/` 命令。**在输入框开头打 `/` 就弹出命令提示**并按输入过滤，回车选第一项。命令分三组：Momoko 内置、Agent 自己的命令、技能（见第 7 节）。
- 输入框下面一行是无边框的选择器：上下文占用（点开看已用 / 上限的具体数值）、权限模式（包含「自动」）、模型和推理强度。模型选择是紧凑的级联菜单：当前供应商下的模型 → 更多模型 → 推理强度。**每个模型能选的推理强度不一样**。
- 右侧面板四个标签：改动、文件、任务、会话。任务是后台任务（进行中 / 已完成），不是终端；**子 Agent 点开是它自己的会话**（只读，开在中间的标签里），命令类任务点开看输出。「会话」标签里有：状态、Agent、分支、上下文卡片（分类明细）、Token 用量卡片（输入、输出、缓存命中、思考、缓存写入、缓存命中率、最近一轮）、信息列表（工作区、分支、工作树、复刻自……）、本会话的 MCP（只显示名称）和技能。
- 新会话页：输入框在最下面；右侧「本次会话的设置」里选工作区（包含「不用工作区」，下拉最后一项是**在本页弹窗里添加工作区**，不是跳去管理页）、**添加文件夹**（一次会话可以带多个目录）、是否在独立工作树里运行、本次开启哪些 MCP（只显示名称和开关）。新建时直接套用工作区的默认配置，要改再点开选择器。

**Agent 管理（七个标签，一个菜单一个页面，页内用 `?tab=`）**
- 会话：状态筛选带数量、按标题搜索、每行归档 / 取消归档和删除、勾选后批量归档 / 导出 / 删除；「已归档」筛选下有带确认的「删除全部归档会话」。运行中或等待批准的会话可以展开看进程信息（命令、PID、内存、已运行），只读。**这一页不能停止会话、不能结束进程**，停止只在会话里做；还在运行的会话不能归档。
- 工作区：一行一个，行内「新会话」「查看文件」（本页弹窗浏览目录，只读）「编辑」「⋯」。**没有打开终端**。弹窗：目录从哪来（服务器上已有的目录 / 从 Git 克隆）、名称、目录、默认模型、默认推理强度、默认权限模式、默认开启的 MCP、项目指令（AGENTS.md / CLAUDE.md）。
- 模型供应商：分「官方账号」和「第三方接口」两组。官方账号的登录由 Momoko 保管，同一家可以登录多个账号，各自作为一个供应商被选择；行上显示额度（5 小时、本周，各带重置时间和已用百分比）。第三方接口的表单见第 4.3 节。
- MCP：名称、说明、传输方式（stdio：命令、参数、环境变量；HTTP：地址、请求头）、新会话默认开启、测试连接；支持粘贴 `mcpServers` JSON 导入。
- 技能：列表带启用开关；编辑器是文件列表加文本框，可以增删文件、改路径；可以从压缩包、Git 地址、服务器目录导入。
- 运行时：每个 Agent 一行（安装方式：Momoko 下载并更新 / 用服务器上已有的命令；重新检测；检查更新），可以添加其它 ACP Agent（名称 + 启动命令）。「同时运行的 Agent 进程上限」和「空闲后结束进程」都是**自己输入数字**（后者单位分钟，0 表示不自动结束）。
- 通知：因为 Agent 在服务器上跑，关了网页还在继续，所以要能通知到人。三个时机开关（等待批准时、一轮结束时、出错时）和四种方式（Discord、Telegram、飞书、QQBot），见第 8 节。

## 2. 架构

```
浏览器 ──HTTP / WebSocket──► Momoko 主 server
                              ├─ 会话服务：会话、记录、权限请求、事件广播
                              ├─ ACP 客户端（JSON-RPC over stdio）
                              │     └─ Agent 进程运行器（管道，不是 PTY）
                              │           ├─ claude-agent-acp ──► Claude Code
                              │           ├─ codex-acp ────────► Codex
                              │           └─ 其它 ACP Agent
                              ├─ 配置：工作区 / 供应商 / MCP / 技能 / 运行时 / 通知
                              └─ 通知发送：Discord / Telegram / 飞书 / QQBot
```

- **ACP 客户端**：Go 实现，调研时找到的 SDK 是 `github.com/coder/acp-go-sdk`（`acp.NewClientSideConnection`），`go.mod` 里还没有，需要加。
- **进程运行器要新写**：`pkg/servercore` 是基于 PTY 的，承载不了 stdio 上的 JSON-RPC。需要一个用管道接 stdin / stdout、单独收 stderr 的子进程运行器，负责启动、空闲回收、并发上限、异常退出上报。
- **长连接**：对话事件走原始 WebSocket，照现有做法在 service 上实现 `RegisterWsServer`，在 `internal/server/http.go` 注册，在 `internal/server/authz.go` 的 `wsRoutePermissions` 里加权限。Kratos 请求有 15 秒超时，Agent 的一轮可能跑很久：发起一轮的接口要立刻返回，后续靠 WebSocket 推事件；需要脱离请求生命周期的地方用 `context.WithoutCancel`（仓库里已有同样用法）。
- **会话和 Agent 进程解耦**：进程可以空闲回收，下次打开会话时用 ACP 的加载 / 恢复把上下文接回来。浏览器断开不影响进程，重连后补发缺的事件，所以事件要落库并带序号。
- **远程节点**：管理页和 Code 页要能在远程节点上用，走现有的节点代理（`internal/server/node_proxy.go`、`node_policy.go`）。注意：`internal/server/grpc.go` 目前注册的服务比 `node_policy.go` 允许的少，新增 Agent 服务时两边都要加，并顺手核对现有的缺口。
- **密钥**：API Key、MCP 的环境变量值和请求头、通知渠道的令牌都用 `pkg/secretbox` 加密保存，接口只返回脱敏后的后几位。
- **适配器**（调研时的情况，实现前以各自仓库当前的 README 为准）：
  - Claude Code：`@agentclientprotocol/claude-agent-acp`，有打包了 Claude CLI 的独立发行包；相关环境变量 `CLAUDE_CODE_EXECUTABLE`、`CLAUDE_AGENT_ACP_PROTOCOL`；支持通过 `_meta.claudeCode.options` 透传 Claude SDK 的选项。
  - Codex：`@agentclientprotocol/codex-acp`（zed-industries 的那个已归档）；相关环境变量 `CODEX_API_KEY`、`OPENAI_API_KEY`、`NO_BROWSER`、`CODEX_CONFIG`、`MODEL_PROVIDER`、`CODEX_PATH`、`INITIAL_AGENT_MODE`。

## 3. ACP 能力对照

状态是 2026-11 调研时的情况。「需要声明」的能力，Agent 没声明就不能用，对应的界面元素不出现。

| 界面上的东西 | ACP 里对应什么 | 状态 |
|---|---|---|
| 新建会话（工作目录 + MCP 列表） | `session/new` 的 `cwd`、`mcpServers` | 稳定。stdio 类型的 MCP 必须支持，HTTP 类型按 Agent 能力 |
| 打开历史会话 | `session/load`、恢复 | 已定稿，需要声明 |
| 会话列表、删除、关闭 | 会话列表 / 删除 / 关闭 | 已定稿，需要声明。Momoko 自己也存一份会话表，列表以自己的为准 |
| 发消息、停止 | `session/prompt`、`session/cancel` | 稳定 |
| 批准卡片 | `session/request_permission` | 稳定 |
| 工具调用、内联 diff、计划、图片和文件引用 | 会话更新里的工具调用、计划、内容块 | 稳定 |
| `/` 命令里 Agent 那一组 | `available_commands_update` | 稳定 |
| 模型、推理强度、权限模式的选择器 | 会话配置项（`mode`、`model`、`thought_level` 等类别），`session/set_config_option` | 已定稿。**客户端只能在 Agent 列出的值里选** |
| 上下文已用 / 上限 | `usage_update` 的 `used`、`size`（还有可选的 `cost`） | 已定稿 |
| 上下文分类明细 | ACP 没有。Claude Agent SDK 有 `getContextUsage()`，`/context` 也能在非交互模式用 | 不在协议里，适配器是否转出要实测 |
| 每轮 token、Token 用量卡片、缓存命中率 | 一轮结束时的 `usage`（总数、输入、输出、思考、缓存读、缓存写） | **Draft 提案**，口径还没定 |
| 添加文件夹 | `additionalDirectories`（新建、加载、恢复时整体给一个数组） | 2026-06 定稿，需要声明 |
| 复刻对话、在新工作树里复刻 | `session/fork`，参数同加载会话，可以给不同的 `cwd` | **在不稳定标志后面**，需要声明；Agent 可以拒绝换目录的复刻 |
| 子 Agent 的会话 | Claude 适配器列出支持子 Agent 的记录 | 适配器自己的能力，Codex 侧要实测 |
| 会话标题 | 会话信息更新（Agent 给标题） | 已定稿。用户重命名存在 Momoko 自己的库里，不回写 Agent |
| 压缩上下文 | 压缩相关提案没定稿 | 用 Agent 自己的 `/compact` 命令 |
| 官方账号额度 | ACP 没有 | 见第 9 节 |
| 第三方接口 | 供应商相关提案没定稿 | 启动 Agent 进程时用环境变量或配置注入，见第 4.3 节 |
| 会话里某个 MCP 连没连上、有几个工具 | ACP 不上报 | 不显示。连接状态只在管理页的「测试连接」里由 Momoko 自己测 |

「在新工作树里复刻」的做法：Momoko 自己用 `git worktree add` 建工作树（名字自动生成），再以那个目录调 `session/fork`。新会话页的「在独立工作树里运行」同理，先建工作树再以它为 `cwd` 新建会话。

## 4. 数据与配置

用 ent 建表，筛选、搜索、计数、统计全部写在 SQL 里，不要查出来再在内存里处理。业务错误统一 400，凭证错误 401。

### 4.1 会话

- 会话表：标题（用户重命名后的）、Agent、工作区、附加文件夹、工作树名、供应商、模型、推理强度、权限模式、状态（运行中 / 等待批准 / 空闲 / 出错 / 已归档）、Agent 侧的会话 ID、复刻来源（父会话 ID）、是否已移到外层、最近活动时间、累计 token（Agent 给了才累加）。
- 事件表：会话 ID、序号、类型、内容。用于回放、断线重连补发和导出记录。
- 进程信息（PID、内存、已运行）是运行器的实时状态，不落库。

### 4.2 工作区

名称、目录、Git 信息（是否仓库、当前分支，实时读）、默认模型（连带确定供应商和 Agent）、默认推理强度、默认权限模式、默认开启的 MCP。项目指令文件（AGENTS.md / CLAUDE.md）直接读写工作区目录里的文件，用 `pkg/file` 的受限访问，不另存一份。「查看文件」同样只读地列目录。

### 4.3 模型供应商

- 官方账号：哪家、名称、谁可以用（只有我自己 / 所有能用 Agent 的成员）、登录状态。登录流程是 Momoko 在服务器上发起，给用户一个授权链接，用户在自己浏览器里登录后把授权码贴回来。每个账号用单独的配置目录隔离，启动 Agent 进程时指到对应目录。
- 第三方接口：名称、接口协议（Anthropic 兼容给 Claude Code 用，OpenAI 兼容给 Codex 用）、接口地址、API Key、**模型目录**、主模型和快速模型（或默认模型）、额外环境变量。
- 模型目录参考 dsh 的做法：「获取可用模型」从接口拉列表，也可以手动添加模型 ID。每个模型有「模型选项」，里面是**推理等级表：每行一个「等级」加「API 参数值」**。自定义接口的模型 Agent 不知道它支持哪些推理强度，必须由用户在这里声明；会话里的推理强度菜单只列这里声明过的等级，一行都没有就不出现这个菜单。
- 「添加一级」按 off → low → medium → high → xhigh → max 的顺序自动带出比当前最高一档更高的那一档（等级名和参数值一起填好，off 的参数值留空表示不带这个参数）；中间有缺的按顺序补进对应位置；六档全有之后再加才是空白行。新模型默认带 off / low / medium / high。

### 4.4 MCP、技能、运行时、通知

- MCP 服务器：名称、说明、传输方式、命令 + 参数 + 环境变量或地址 + 请求头、新会话默认开启。新建会话时把选中的那些放进 `mcpServers`。
- 技能：名称、说明、来源、是否启用，文件放在服务器上的技能目录里，只存一份；起会话时经 ACP 的 additionalDirectories 把启用的技能目录交给 Agent，不复制。
- 运行时：每个 Agent 的安装方式和启动命令、检测结果；全局的并发上限和空闲时长放在现有的 `configs` 键值表里。
- 通知：三个时机开关；每种方式的配置和是否启用。

## 5. 路由与文件落点（建议）

- 接口定义放 `api/proto/v1/` 下新的 proto，`make api` 生成；biz / data / service 照现有分层放在 `internal/` 下。
- 前端：`frontend/src/views/agent/` 下分 Code（会话进行中、新会话）和管理页；菜单加一个「Agent」分组，两项：Code、Agent 管理；管理页的七个标签用 `?tab=sessions|workspaces|providers|mcp|skills|runtimes|notify`，定义照 `frontend/src/config/pageGroups.ts` 的写法；文案写在 `frontend/src/locales/extra/agent.ts`。
- 代码和 diff 展示用项目里已有的 Monaco（DiffEditor 目前还没接，需要接上）；对话里的 Markdown 用已有的 markdown-it。

## 6. 逐页对照

实现每一页前先读对应的原型文件，模板是布局，`renderVals()` 里每个处理函数就是那个控件应该有的效果。几处容易漏的：

- `Main.dc.html`：会话栏的 `groupOf` / `nest`（分层、折叠、展开显示、复刻缩进）、会话菜单和重命名、删除两个弹窗、标签页（对话 / 文件 / 子 Agent）、批准卡片的四种状态（等待、允许、拒绝、停止）、输入区的各个弹层、右侧四个标签。文件里还留着「切换分支」「放进工作树」两个旧弹窗的模板，已经没有入口，不要实现。
- `AgentNewPC.dc.html`：添加工作区弹窗、添加文件夹、Agent 和模型的级联选择。
- `AgentProvidersPC.dc.html`：`modelRows` 里的推理等级表和 `addRow` 的预设规则，官方账号登录弹窗的两步。
- `AgentMcpPC.dc.html`：`doPaste` 对 `mcpServers` JSON 的解析。
- `AgentSessionsPC.dc.html`：归档规则、删除全部归档的确认。

手机端目前只有 Code 页的原型（会话列表、会话菜单、附件、权限模式、模型和推理强度、MCP 开关都是底部面板）。管理页的手机版没画，照 `../IMPL_BRIEF.md` 的规则做：列表行改成卡片，表单单列。

## 7. 内置命令和内置 MCP

`/` 命令的第一组是 Momoko 内置的，目前两个：

- `/install-skill`：把一个技能装到 Momoko，后面跟 Git 地址或压缩包链接。
- `/install-mcp`：把一个 MCP 服务器装到 Momoko，后面跟它的地址或安装说明。

做法：Momoko 给每个会话带一个自己的内置 MCP 服务，提供「安装技能」「添加 MCP 服务器」这类工具，再配上内置技能教 Agent 怎么用。用户发出命令后，Agent 去读对方的说明，然后调用工具写进 Momoko 的配置。因为是工具调用，照常走批准卡片，批准后才生效，装好的东西出现在 Agent 管理对应的页面里。命令本身是客户端这边的快捷方式，展开成一条发给 Agent 的消息。

## 8. 通知

- 时机：等待批准时、一轮结束时、出错时（进程异常退出，或供应商登录过期）。
- 方式和各自要填的：Discord（Webhook 地址）、Telegram（Bot Token、Chat ID）、飞书（机器人 Webhook 地址、可选的签名密钥）、QQBot（AppID、AppSecret、发给谁）。必填项填完才能保存，保存后自动启用；每种都能发一条测试。
- **QQBot 的字段是按 QQ 官方机器人写的，用户还没确认**。如果实际用的是 OneBot 一类（HTTP 地址加 Token），字段要换，实现前先问。
- 通知的内容（标题、是否带会话链接、能否直接在消息里批准）原型没有画，实现前先和用户确认。
- 站内通知（右上角铃铛）照常发，不在这一页配置。

## 9. 需要实测的清单

这些直接决定界面上的东西出不出现，动手前先用两个适配器各跑一遍：

1. Claude 适配器在当前协议版本下是否提供会话列表、恢复、会话配置项（它的 README 把其中一些列在 v2 草案下）。
2. Codex 适配器的会话恢复。
3. 两个适配器是否发 `usage_update`，一轮结束时是否带 token 用量，字段口径（缓存写入算不算进输入）。
4. 两个适配器是否声明 `additionalDirectories` 和 `session/fork`，复刻时能否换工作目录。
5. 上下文分类明细能否从 Claude 适配器拿到；拿不到时在会话里发 `/context` 再解析是否可行。注意有报告说 `getContextUsage()` 在某些接入方式下每次调用会产生额外计费，不要每轮自动刷新，打开面板时取一次。
6. 官方账号额度：Claude 一侧有资料说适配器把 SDK 的限额事件放在 `_claude/rateLimit` 扩展字段里转发，但百分比可能平时不给；Codex 一侧有 `account/rateLimits/read`，但那是它自己的 app-server 协议，不是 ACP。读不到百分比时只显示重置时间或者不显示。
7. 第三方接口怎么注入：Claude Code 走哪些环境变量、Codex 走 `MODEL_PROVIDER` / `CODEX_CONFIG` 是否够用。
8. 用户在模型目录里填的推理等级参数值，怎么对应到各 Agent 自己的推理强度设置。
9. 官方账号多账号登录：每个账号一个配置目录的做法在两家 CLI 上是否都成立，授权码流程在无浏览器的服务器上怎么走（Codex 有 `NO_BROWSER`）。
10. Codex 的子 Agent 记录能否像 Claude 一样拿到。
